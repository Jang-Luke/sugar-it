# sugar-it Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 등록된 모든 호스트의 공유 폴더를 CLI, 네이티브 GUI, WebDAV 마운트로 탐색하고 자유롭게 복사·이동하는 크로스 플랫폼 패키지를 만든다.

**Architecture:** 호스트마다 Go 데몬이 mTLS Peer API, 루프백 Control API, 루프백 WebDAV를 제공한다. 멤버 목록은 가십으로 풀 메시를 이루고, 전송은 목적지 호스트에서 실행되어 이어받기와 SHA-256 검증을 거친다. CLI와 Wails GUI는 모두 Control API의 클라이언트다.

**Tech Stack:** Go 1.27, `os.Root`, `net/http`(HTTP/2), `crypto/tls`, cobra v1.10.2, `golang.org/x/net/webdav`, Wails v2.17.1, Svelte + TypeScript + Vite, Vitest, GoReleaser.

**Spec:** `docs/superpowers/specs/2026-11-02-sugar-it-design.md`

## Global Constraints

- Go 모듈은 `sugarintegration`(루트)과 `sugarintegration/desktop`(별도 모듈, `replace sugarintegration => ../`)으로 나눈다. 루트 모듈은 cgo와 Wails에 의존하지 않는다. 별도 모듈에서 루트의 `internal/`을 import할 수 있음은 Go 1.27.3에서 확인했다.
- `CGO_ENABLED=0 GOOS={linux,darwin,windows} go build ./...`가 매 태스크 끝에 통과해야 한다.
- 기본 포트: Peer `:7443`, Control `127.0.0.1:7444`, WebDAV `127.0.0.1:7445`.
- Peer API는 TLS 1.3 이상. 멤버가 아닌 인증서는 `/v1/pair` 외 전부 403.
- 공유 파일 접근은 `os.Root`로만 한다. 경로 문자열을 이어 붙여 `os.Open`하지 않는다.
- 토큰을 로그, 명령행 인자, 오류 메시지에 남기지 않는다.
- 비밀 파일은 `0600`, 설정 파일은 임시 파일 후 rename으로 저장한다.
- 오류는 스펙 6절의 코드만 쓰고 `vfs.E`로 만든다.
- 이름 규칙 `[a-z0-9-]{1,32}`, 예약어 `local`.
- GUI 문구는 한국어(`desktop/frontend/src/ko.ts`에 집약), CLI 문구는 영어.
- `graft/`는 외부 도구의 캐시이므로 `.gitignore`에 넣고 수정하지 않는다.
- 계획은 스펙을 근거로 삼는다. 값이 충돌하면 스펙을 따르고 차이를 보고한다.

## Review Focus

1. **전송 중 연결 끊김이나 데몬 재시작:** 끝까지 이어받아 내용이 원본과 같아야 하고, 이동은 검증 전에 원본을 지우면 안 된다. (Task 4, 5, 11)
2. **자기 자신이나 하위로 이동, 겹치는 공유:** 시작 전에 거부하고 데이터가 줄어들지 않아야 한다. (Task 2, 5)
3. **전송 중 원본 수정:** 섞인 파일을 만들지 않고 재시작하거나 `changed`로 실패해야 한다. (Task 4)
4. **목적지 OS에서 쓸 수 없는 이름과 대소문자만 다른 이름:** 해당 항목만 실패하거나 충돌 처리하고, 이동이면 원본을 남겨야 한다. (Task 2, 5)
5. **공유 밖을 가리키는 심볼릭 링크와 순환 링크:** 공유 밖 내용을 노출하지 않고 전송을 멈추지 않아야 한다. (Task 2, 5)
